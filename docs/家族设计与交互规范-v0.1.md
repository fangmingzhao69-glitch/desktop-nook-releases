# 家族设计与交互规范 v0.1

确认日期：2026-11-06。

已确认的原则：基础交互统一，核心功能交互按各软件用途设计。适用范围为当前桌面收纳软件及后续效率工具；命名采用“母品牌＋功能名”。

母品牌名称、最终图标、配色仍待确定。“归屿”为概念稿示例，“轻匣”保留为备选。本规范不表示已批准改名或将概念图直接替换到正式程序。

## 1. 品牌与命名

- 一个统一母品牌，各产品使用清楚的功能名，避免每款软件各造一套命名结构。
- 示例：归屿·桌面、归屿·笔记、归屿·文件、归屿·流程。后三项仅用于检验家族扩展性，不代表已经立项或开发。
- 完整名称用于安装、设置、更新和首次介绍；空间较小时可在上下文清楚的前提下缩写功能名。
- 正式更名须保留既有数据、分类、偏好和更新链路，不能因改名建立另一份空白用户配置。

## 2. 图标与视觉

- 家族共享主轮廓、比例、圆角、线条或块面的厚度，以及明暗方向。
- 产品通过中心功能符号区分，辅助色帮助识别；单色下仍需能够区分，不能只靠换颜色。
- 深浅背景和任务栏小尺寸均要单独检查。方案图中的缩略图仅作设计参考，正式图标另行生成并验收各尺寸资源。
- 品牌色、产品辅助色与成功、警告、错误等状态色分别定义，功能身份不能混同错误状态。
- 主窗口、菜单、设置、更新、空状态和错误提示共享设计参数及组件状态。
- 文字按当前屏幕 DPI 原生排版和像素对齐，不整体缩放文字位图；阴影与文字内容分层。

## 3. 家族统一的基础交互

| 项目 | 共同规则 | 可按产品变化的部分 |
| --- | --- | --- |
| 按钮 | 相同动作使用一致的名称和视觉层级；优先使用“动词＋对象” | 收纳项目、新建笔记、添加文件、新建流程 |
| 确认与取消 | 确认文字说明实际动作；取消保留此前状态 | 保存、删除、移回桌面等具体动作 |
| Esc | 优先取消当前拖动、关闭菜单或退出临时操作，再处理窗口级行为 | 桌面面板可收起；编辑器需处理未保存内容 |
| 右键菜单 | 就近操作、可用状态、悬停反馈、字号及间距统一 | 各对象提供适合它的命令，不塞入无关功能 |
| 拖拽 | 显示有效落点和结果预期；无效落点或 Esc 不提交操作 | 图标排序、文件移动、笔记排序、节点连接 |
| 保存反馈 | 明确区分保存中、已保存、保存失败；失败保留可恢复内容 | 自动保存、手动保存或运行任务保存时机 |
| 删除与移除 | 明确对象和影响范围，优先可撤销或可恢复 | 移除入口、删除笔记、删除文件不能用同一含糊名称 |
| 错误提示 | 说明哪一步失败、当前内容状态和可执行的处理方法 | 根据网络、占用、权限、编辑冲突提供对应处理 |
| 键盘与焦点 | 焦点可见，通用确认、取消与导航语义稳定 | 功能快捷键按产品定义并在界面中说明 |

## 4. 通用设置统一语义，不强行统一默认值

- 开机自启、主题、关闭行为、版本信息和更新入口，采用一致的名称与组织方式。
- 用户明确取消的勾选必须作为 false 保存，不能当作“未设置”恢复默认值。
- 设置按产品明确归属。主题等未来可提供家族共享选项，但不能擅自把一个产品的自启或关闭偏好同步到其他产品。
- “关闭窗口”与“退出程序”的结果必须明确。“退出程序”需处理尚未保存的内容和运行中的任务。
- 笔记或流程产品应按数据保存和任务状态决定默认行为，不能照搬桌面启动器的默认设置。
- 更新前后核对分类、收纳记录和用户偏好。先提交推送、发布 GitHub 正式包，再由软件提示，用户确认后下载安装。

## 5. 核心操作按功能设计

以下为设计边界示例，后续产品另行做需求设计。

| 产品 | 主要界面 | 主要操作 | 不应强行套用的习惯 |
| --- | --- | --- | --- |
| 桌面收纳 | 分类标签、图标网格 | 单击启动，拖入收纳，拖回桌面，分类内排序 | 不把启动动作改成编辑器的点击编辑 |
| 笔记 | 笔记列表、编辑区 | 选择笔记、输入编辑、自动保存并显示状态 | 不因点击窗口外就隐藏编辑器或丢失内容 |
| 文件工具 | 文件列表或网格、路径与预览 | 按产品定义选择和打开方式，拖拽显示移动或复制意图 | 不把“从列表移除”当成“删除实际文件” |
| 流程工具 | 节点画布、属性区、运行结果 | 选择和移动节点、连接步骤、配置和运行 | 不让拖动节点触发桌面图标的“移回桌面”行为 |

## 6. 当前桌面软件的设计基线

- 保留顶部标签切换、一个连续图标网格、默认六列；窗口尺寸变化时按现有规则换行。
- 保留任务栏入口展开与收起、单击启动、直接拖拽整理，以及已选的关闭行为。
- 明确区分“移回桌面”“移除入口”“删除实际内容”，操作含义不因换品牌而变化。
- 已删除的“未分类”保持删除；已有文件、文件夹、快捷方式、分类和排列顺序完整保留。
- 界面换肤时同步设计主面板、图标/分类右键菜单、设置、更新确认与下载、重命名、空状态和错误提示。
- 本地用户数据与恢复记录不进入 GitHub。

## 7. 后续设计顺序与验收

1. 确定母品牌与图标骨架：保留现有候选，比较名称、主标和产品图标的组合。
2. 固定视觉参数：字体、颜色、间距、圆角、层级和组件状态；配套深浅背景示例。
3. 制作当前桌面软件的完整界面稿，验证主要操作和弹窗比例，再扩展其他产品示例。
4. 按界面稿实现并验收：清晰度、实际任务完成、键鼠操作、偏好和全部收纳内容保留。
5. 按既定 GitHub 发布和用户确认更新流程交付。

仅调整本规范时提交文档即可，不增加程序版本或生成更新提醒。后续功能与界面实现仍需完成对应验证和正式发布。
