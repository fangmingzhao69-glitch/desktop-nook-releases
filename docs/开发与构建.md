# 开发、测试与发行

以下命令从仓库根目录运行，使用 PowerShell 7。需要 Windows 和 .NET 10 SDK。

## 编译与运行

```powershell
dotnet build native/DesktopNook.App -c Release
dotnet run --project native/DesktopNook.App -c Release
```

正常运行会操作真实桌面及当前用户数据。开发调试建议先使用隔离模式：

```powershell
$profile = Join-Path $env:TEMP ('DesktopNook-dev-' + [guid]::NewGuid().ToString('N'))
dotnet run --project native/DesktopNook.App -c Release -- --sandbox $profile
```

隔离桌面为 `<profile>/Desktop`，数据为 `<profile>/Data`，回收站及偏好使用测试状态。不要把日常桌面或工作文件夹作为隔离根目录。

## 构建单文件发行版

```powershell
pwsh -NoProfile -File native/scripts/Build.ps1
```

脚本重新生成多尺寸 ICO、执行核心检查，并发布含运行时的 Windows x64 单文件程序，输出到 `native/artifacts/win-x64/DesktopNook.exe`。已完成核心检查且只需重复打包时可加 `-SkipTests`。

## 测试

核心测试不依赖第三方测试框架：

```powershell
dotnet run --project native/DesktopNook.Tests -c Release -- native/test-results/core.json
```

原生测试必须运行在可交互的 Windows 桌面，且使用新建专用目录。部分检查短暂操控鼠标，期间请暂停其他鼠标操作。

```powershell
$exe = (Resolve-Path native/artifacts/win-x64/DesktopNook.exe).Path
$profile = Join-Path $env:TEMP ('DesktopNook-ui-' + [guid]::NewGuid().ToString('N'))
$test = Start-Process -FilePath $exe -ArgumentList @('--sandbox', ('"' + $profile + '"'), '--ui-self-test') -PassThru
$test.WaitForExit()
Get-Content (Join-Path $profile 'native-verification.json')
```

将 `--ui-self-test` 替换为 `--size-self-test` 可检查预设尺寸、固定图标大小、真实鼠标缩放、偏好保存及版本文字。尺寸检查报告为 `sizing-verification.json`，截图也在该隔离目录中。

替换为 `--order-self-test` 可检查分类页和全部页真实鼠标直接排序、松手保存、Esc 取消、无效落点、拖到标签移动分类以及“全部”汇总顺序，报告为 `ordering-verification.json`。同样必须使用新的隔离目录。

使用 `--category-self-test --keep-open-verification` 可验证“未分类”删除入口、取消/确认、图标接收分类、继续收纳及最后一个分类保护，报告为 `category-deletion-verification.json`。该专用测试在写出结果后结束自己的进程。

原生 UI 检查会等待右键菜单绘制完成，并验证截图包含可见背景与文字；空白截图会使检查失败，不再保存为通过证据。

自启和关闭行为使用专用隔离目录检查：

```powershell
$profile = Join-Path $env:TEMP ('DesktopNook-startup-' + [guid]::NewGuid().ToString('N'))
pwsh -NoProfile -File native/scripts/Verify-StartupExit.ps1 -Exe $exe -Root $profile
```

脚本等待窗口、激活和菜单控件实际就绪，检查重复自启不会弹出面板、关闭收起、关闭退出及菜单退出。失败时也输出 `startup-exit-verification.json`，并尝试关闭自己的隔离进程。此检查不执行 Windows 重启。

日常程序已运行时，可单独检查任务栏连续点击行为：

```powershell
pwsh -NoProfile -File native/scripts/Verify-Taskbar.ps1 -Exe 'C:\实际安装目录\DesktopNook.exe' -Output "$env:TEMP\DesktopNook-taskbar.json"
```

将路径替换为正在运行的安装版或免安装版，输出目录须已存在。脚本按 EXE 路径查找进程，支持英文和中文文件名；会短暂操控鼠标，并在结束时恢复鼠标位置及原来的收起状态。测试时只保留一个具有相同任务栏身份的应用窗口，避免 Windows 将多个实例分组为缩略图选择器。

在线更新专项验证：

```powershell
$report = Join-Path $env:TEMP ('DesktopNook-update-' + [guid]::NewGuid().ToString('N'))
$test = Start-Process -FilePath $exe -ArgumentList @('--verify-online-update', ('"' + $report + '"'), ('"' + $exe + '"')) -PassThru
$test.WaitForExit()
Get-Content (Join-Path $report 'online-update-verification.json')
```

加 `--live` 时会访问当前仓库的真实最新正式版并下载；应在本地程序与该发行版对应时使用。

`--live-verify`、`--collection-inventory` 等维护入口会读取真实本机数据；部分入口可改变真实桌面状态，`--collection-inventory ... --apply` 会执行恢复操作。它们不属于常规测试命令，不应在日常数据上随意运行。

## 构建安装包

先安装 Unicode NSIS，将 `makensis` 加入 PATH。单文件发行版构建完成后：

```powershell
makensis /V2 native/scripts/Installer.nsi
```

默认输出为 `native/artifacts/DesktopNook-Setup.exe`。安装器要求无需管理员权限的当前用户安装，覆盖升级沿用登记路径。可用 `/DOUTPUT=完整路径` 自定义产物位置，用 `/DPAYLOAD=完整路径` 指定单文件 EXE。

安装器源码是 UTF-16，`.gitattributes` 将其作为二进制保存以免被 Git 换行转换损坏。修改时应保留编码。

## 发行新版本

1. 更新 `native/DesktopNook.App/DesktopNook.App.csproj` 的版本，并同步 `native/scripts/Installer.nsi` 中的版本资源和安装登记版本。
2. 在 `native/releases/` 编写版本说明。
3. 完成所需验证；提交所有源码和版本说明，并用 `git push origin main` 推送到 GitHub。
4. 从刚推送的提交重新构建正式 EXE 和安装包，再使用本机登录的 GitHub CLI 发布：

```powershell
pwsh -NoProfile -File native/scripts/Publish-Release.ps1 `
  -Executable native/artifacts/win-x64/DesktopNook.exe `
  -Installer native/artifacts/DesktopNook-Setup.exe `
  -NotesFile native/releases/v新版本.md
```

脚本发布 `DesktopNook-win-x64.exe`、`DesktopNook-Setup.exe`、`SHA256SUMS.txt`：先上传草稿并校验 GitHub 返回的哈希，再公开为最新版本。草稿上传失败可重跑续传；已公开的同版本文件不覆盖。加 `-VerifyOnly` 可核验既有产物。

发布脚本检查工作区干净、EXE 的提交标识等于当前提交、当前提交已推送到 GitHub main；发行标签明确绑定该提交。不会自动提交或推送源码。改变发布仓库时，需要同时调整发布参数和 `OnlineUpdater.Repository` 中的客户端来源限制。

发行包公开后，旧版通过 GitHub Releases 检测到更新。0.11.3 起启动检查、运行中每小时检查，打开面板时距上次检查超过 15 分钟会补查；新版提示显示在面板底部。仅检查不下载，用户点击并确认后才下载并执行更新。日常使用的本机程序也遵循此流程，不在 GitHub 发布前直接覆盖。

## 仓库边界

仅源码、必要图标和文档进入 Git。`bin/`、`obj/`、`artifacts/`、`test-results/`、本机收纳记录与恢复备份被忽略。发行 EXE 放在 Releases，不放进 Git 历史。
