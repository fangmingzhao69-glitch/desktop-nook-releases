# 开发、验证与发行

从仓库根目录运行。需要 Windows、.NET 10 SDK、PowerShell；安装包另需 Unicode NSIS 3。运行轻量版需要 .NET 10 Windows Desktop Runtime x64；SDK 仅供开发，不要求用户安装。当前机器 SDK 为 10.0.400。

## 编译与隔离运行

```powershell
dotnet build native/DesktopNook.App -c Release
$nookSandbox = Join-Path $env:TEMP ('Qingxia-dev-' + [guid]::NewGuid().ToString('N'))
dotnet run --project native/DesktopNook.App -c Release -- --sandbox $nookSandbox
```

普通运行默认使用真实桌面和数据。开发不要省略 sandbox，也不要把真实桌面当作隔离根目录。

## 核心与原生检查

```powershell
dotnet run --project native/DesktopNook.Tests -c Release -- native/test-results/core.json
pwsh -NoProfile -File native/scripts/Build.ps1
```

Build.ps1 重新生成图标、运行核心与游戏物理检查并发布依赖共享 .NET 10 Windows Desktop Runtime x64 的轻量单文件，输出 `native/artifacts/win-x64/DesktopNook.exe`。已有通过证据且仅重复打包时可加 `-SkipTests`。

```powershell
$nookExe = (Resolve-Path native/artifacts/win-x64/DesktopNook.exe).Path
$nookSandbox = Join-Path $env:TEMP ('Qingxia-ui-' + [guid]::NewGuid().ToString('N'))
$nookTest = Start-Process -FilePath $nookExe -ArgumentList @('--sandbox', ('"' + $nookSandbox + '"'), '--ui-self-test') -PassThru
$nookTest.WaitForExit()
Get-Content (Join-Path $nookSandbox 'native-verification.json')
```

原生检查需要交互桌面，会短暂操作鼠标；仅在独立目录运行。不要同时操作真实收纳内容。

| 入口 | 用途 |
| --- | --- |
| `--billiards-self-test`（配合 --sandbox） | 台球鼠标输入、物理帧/暂停、IPC 成绩、30 次启停、维护及父子异常退出、数据不变及内存采样 |
| `--size-self-test` | 预设/自由尺寸、图标尺寸和偏好 |
| `--order-self-test` | 拖动排序、取消和分类间移动 |
| `--category-self-test` | 分类删除及最后分类保护 |
| `--verify-online-update 输出目录 候选EXE` | 下载/来源/哈希/版本、取消与损坏拒绝；加 `--live-check` 仅检查真实元数据；`--live` 另下载真实发行包 |
| `--verify-update 输出目录 旧EXE 候选EXE` | 受控复制后的更新助手与数据保留 |

自启/关闭、任务栏、安装器脚本位于 `native/scripts/Verify-*.ps1`，先读隔离约束再运行。安装器验证必须配合专用 TESTROOT 包，不在日常数据上做卸载回归。维护恢复入口不是常规测试入口，详见交接文档。

## 图标

`Assets/AppIconDrawing.xaml` 是权威矢量源。Make-Icon.ps1 分别渲染 16/20/24/32/40/48/64/96/128/256 像素 ICO 和 512 像素 PNG。构建脚本用独立 STA PowerShell 执行，不修改系统全局策略；不要把带背景的预览图放入程序资源。

## 安装包

Installer.nsi 为 UTF-16，修改时保留编码。NSIS 加入 PATH 后：

```powershell
makensis /V2 native/scripts/Installer.nsi
```

本机共享编译器未加入 PATH，可用：

```powershell
& 'E:\cxgj\DeepSeekHarness zhuomianduan\builder-cache\nsis-3.0.4.1\nsis-3.0.4.1-1mx3n\makensis.exe' /V2 native/scripts/Installer.nsi
```

默认输出 `native/artifacts/DesktopNook-Setup.exe`。可指定 PAYLOAD、OUTPUT；TESTROOT 用于专用隔离数据/登记键。正常覆盖升级不执行全部恢复。

## 发布

1. 更新 App.csproj、NSIS 产品/登记版本，并新增当前版本说明。内部兼容标识保持不变，详见交接。
2. 完成适用验证，提交并推送源码。
3. 从已推送提交重新构建 EXE 和安装包。
4. 使用本机已登录的 GitHub CLI 发布：

```powershell
pwsh -NoProfile -File native/scripts/Publish-Release.ps1 `
  -Executable native/artifacts/win-x64/DesktopNook.exe `
  -Installer native/artifacts/DesktopNook-Setup.exe `
  -NotesFile native/releases/v新版本.md
```

脚本要求工作区干净、EXE 提交标识对应当前已推送源码，EXE/安装包版本一致。先草稿上传三文件，核对服务器 SHA-256 后公开。失败可续传草稿；同版本已公开文件不可覆盖。`-VerifyOnly` 仅核对，不发布。

后续代码改动使用新版本号。0.12.2 正式包保留原哈希；GitHub 限流不能视作没有新版，也不把个人令牌放入客户端。

## 清理后重建

bin/obj/artifacts/测试目录可重建，不依赖旧原型或历史安装包。本机正式交付只保留 `发布/轻匣-v0.15.0/`；Git 历史与 GitHub Releases 保留。

## 运行时补装验证（0.12.6）

RuntimeCheck.nsh 在停止旧程序前检测运行时，缺少时经用户确认执行 RuntimeBootstrap.ps1。该脚本使用 Windows 自带的 .NET Framework / Windows PowerShell，不依赖待安装的 .NET 10；只为微软官方安装器请求管理员授权，轻匣主安装器始终保持原用户身份。

DotNetRuntime.json 固定微软 10.0 官方发布清单中的 x64 Windows Desktop EXE、版本和 SHA-512。更新该文件时核对 https://builds.dotnet.microsoft.com/dotnet/release-metadata/10.0/releases.json，不能替换成 SDK、其他架构或第三方源。安装前还验证微软 Authenticode 签名。

使用 Windows PowerShell 执行 Verify-RuntimeBootstrap.ps1 -NSIS 编译器完整路径，可以在独立临时目录验证 7 个分支与元数据/哈希/签名拒绝逻辑；测试使用假组件退出码，不安装或卸载本机运行时。RuntimeBootstrap.ps1 -ManifestPath DotNetRuntime.json -VerifyDownloadOnly -OutputDirectory 独立目录可真实下载校验而不执行安装。真实无运行时电脑的端到端验证应在额外测试机或虚拟机完成，禁止卸载本机共享运行时来制造测试条件。

动画验证包含在 --ui-self-test 中，仅允许 --sandbox。输出 motion-verification.json、motion-stress.json；开启/关闭各 100 轮，无强制 GC，记录活动时钟、CPU 与专用提交。效果和验收边界见动画实施方案。
可见性单独使用 --sandbox 独立目录 --motion-visibility-self-test；采真实屏幕帧并生成 motion-visibility.json。探针使用中性背景窗遮住非测试内容，不绕过任务栏定位。
常驻检查：--sandbox 独立目录 --memory-self-test，输出 residency-verification.json，覆盖 5 秒闲置释放及原生恢复/重复唤醒。Measure-Memory.ps1 以全新合成数据比较私有工作集、总工作集和专用提交；默认 10 次完整开合，可用 -Cycles 100。私有工作集使用 PROCESS_MEMORY_COUNTERS_EX2，需要支持此结构的 Windows（本机 Windows 11）；没有强制 GC 或裁剪工作集。

存储专项使用发布后的单文件运行 --storage-self-test 独立目录，不能只复制多文件 build 的 apphost 执行。正常数据位于安装目录 Data；沙箱 --data-root 可覆盖数据位置但保留原沙箱桌面及实例身份。真实迁移命令 --relocate-storage 源目录 目标Data 核验报告，只在退出程序、完成备份后按用户明确迁移请求使用。

图标台球检查会短暂创建游戏窗口和受控沙箱父进程，生成 billiards-verification.json 与仅含合成图标的 billiards-preview.png；游戏内部测试协议只在已认证且 TestMode=true 的沙箱测试会话开启。原生交互检查依次执行，避免多个检查窗口互相抢焦点。台球窗口的 Topmost 仅在此测试模式开启，用于保证真实鼠标命中属于测试窗口；正式游戏窗口不置顶。

单独性能采样：--sandbox 独立目录 --billiards-perf-test，输出 billiards-performance.json；21 个合成来源、以 1920×1040 逻辑像素屏幕输入计算40% 面积窗口，先测首次击球，再累计三局运动帧，另测最小化帧订阅及 CPU。该采样不设为无人值守常驻任务。

球组专项可拆开运行：--billiards-mouse-self-test 为短时原生鼠标验收；--billiards-protocol-self-test 为 IPC 驱动的完整生命周期检查，均须 --sandbox。后者不移动全局鼠标，游戏测试窗口不置顶，记录 inputMode=ipc-simulation；不能拿它替代原生鼠标证据。两者均正常通过后可避免长时间独占鼠标。

音效原始来源与切片参数见 ThirdPartyNotices/BilliardsAudio-CC0.txt 及 Games.Core/Audio/manifest.json。普通构建直接嵌入 PCM，不联网。需要重新处理录音时，用开发环境的 PyAV / NumPy / SciPy 执行 Import-BilliardsAudio.py 输入目录 输出目录；两个输入文件的名称为 clack.mp3、shots.mp3，处理后的哈希需一并复核。勿替换为无来源或不允许分发的音频。

好友核心：dotnet run --project native/DesktopNook.Network.Tests -c Release -- native/test-results/network-core.json（真实回环 TCP / TLS 与发现）。双端界面：--sandbox 独立目录 --friend-self-test，创建两个独立游戏进程，仅绑定回环；结果 friend-verification.json 不包含邀请信息。Build.ps1 已包含网络核心检查；互动 UI 检查仍须串行。
