# 图标台球接入分析

本轮只完成源码审阅和接入建议，未执行上游游戏、隐藏真实桌面图标、修改收纳数据或更新安装版。

## 审阅依据

仓库：[liuxiaogang-com/desktop-icon-billiards](https://github.com/liuxiaogang-com/desktop-icon-billiards)。审阅提交 `eb8818f378a3adf2cf5e753556e74dcd742af6d1`，代码版本 0.1.5；README 下载介绍仍写 0.1.4，两者不混同。

- `body.py`、`table.py`：圆形碰撞体、击球、摩擦、碰库、瞄准预测、入袋、白球重置及计时。核心计算与 Python 桌面窗口代码分开，适合单独移植。[物理实现](https://github.com/liuxiaogang-com/desktop-icon-billiards/blob/eb8818f378a3adf2cf5e753556e74dcd742af6d1/dib/table.py)
- `overlay.py`：Shell 图像提取、桌面图层和逐图标窗口绘制。游戏展示时记录并隐藏真实 SysListView32，退出时恢复；读取部分图标矩形还使用 Explorer 的远程缓冲区和 ListView 消息。不能把这一层当成普通轻匣面板动画直接套入。[桌面图层实现](https://github.com/liuxiaogang-com/desktop-icon-billiards/blob/eb8818f378a3adf2cf5e753556e74dcd742af6d1/dib/overlay.py)
- `shell.py`、`watchdog.py`：桌面会话日志、恢复和独立异常恢复进程。当前启动用 overlay_only，不在每帧真正移动 Explorer 图标；画面里的运动来自独立图层。部分兼容恢复分支仍包含真实位置和排列标志恢复。
- `runner.py`：游戏期间约 60 Hz 的绘制线程；`ui.py` 为 Tk 控件。依赖 Pillow、pywin32 和 comtypes，PyInstaller 单文件会带入这些运行组件。未实测其 EXE 大小或内存，不给固定数字。
- `rank.py`、`update.py`：独立成绩上传和更新服务；默认上传需选择开启。原路径使用 TEMP/APPDATA，与轻匣刚统一的安装目录 Data 不同。

## 接入选择

| 做法 | 优点 | 对轻匣的影响 |
| --- | --- | --- |
| 更多菜单启动原版 EXE | 最快体验，保留上游完整桌面玩法 | 两套界面、运行组件、更新和目录；真实桌面显示状态需恢复，附加体积/运行占用要另测 |
| 移植 C# 物理与 WPF 游戏画面 | 与现有 .NET 10、图标、数据目录和更新方式一致 | 开发量较大，但可控制游戏生命周期、图标来源及数据边界，推荐 |
| 只把碰撞效果加到收纳面板 | 改动表面上较少 | 容易混淆启动、排序和击球手势，也不能提供完整台球玩法，不作为首版方案 |

推荐做独立的“图标台球”功能，正常启动/排序界面保持现有交互。入口为“更多 → 桌面玩法 → 图标台球”。

## 推荐首版体验

图标来源提供两种：轻匣当前分类/全部，以及 Windows 桌面图标的只读镜像。优先实现收纳图标，复用 `Store.ManagedPath` 和 `SharpIcons`；本机收纳图标较多，当前分类选择也比剩余桌面图标更方便。桌面来源后续通过只读 Shell 枚举接入。

打开独立、桌面尺寸的台球窗口，用图标副本组成球阵；按住蓄力、松开击球，提供瞄准线、进球数、计时、重开和退出。参考上游 15～45 颗的数量范围，球数不足时只复制游戏中的图像，过多时让用户选择分类或限制参与数量。

首版游戏窗口覆盖桌面区域，不隐藏或移动 Explorer 图标，不依赖游戏退出去“还原”真实桌面。这样可保留核心台球体验，并支持最小化、Alt+Tab 和 Esc 退出。它与上游直接嵌入 Explorer 的透明图层模式有区别；若需要原版“只有图标在壁纸上滚动”的效果，另作第二阶段桌面模式，需完整接入会话恢复、显示变化检测及独立异常恢复。

入袋只计分，不调用收纳、删除、移回或排序。游戏快照与 `state.json`、`item-order.json` 分离。若要增加“打入球袋就收进某个分类”的玩法，应另外设计明确的提交动作，不能默认让碰撞触发文件操作。

## 对应的实现模块

| 新模块 | 工作 |
| --- | --- |
| GameIconCatalog | 从所选分类或桌面读取名称和图标，生成只读会话快照 |
| BilliardsPhysics | 移植球体、碰撞、摩擦、球袋和瞄准预测，无 WPF/文件操作依赖 |
| BilliardsWindow | WPF 二维绘制、球杆和辅助线、输入、计时及重开 |
| BilliardsController | 启动、单局去重、退出、会话清理及父程序联动 |
| 本地设置与成绩 | `Data/Games/IconBilliards` 内保存，统一备份及权限 |

推荐同一发行 EXE 增加内部游戏启动模式，在常规单实例入口和 NookStore 初始化之前分流。只有手动开始游戏时创建按需子进程，日常轻匣仍是一个常驻进程；退出游戏即结束该进程，便于回收绘制资源。子进程仅取得图标会话快照，不实例化可写收纳存储，不承接轻匣数据的写入职责。

父程序更新、迁移和明确退出时先关闭游戏并等待确认；游戏进程异常结束时当前模式的真实桌面不需要恢复。若以后加入 Explorer 隐藏模式，必须补独立恢复进程及持久恢复日志，不能仅依靠父程序仍然存活。

沿用主程序更新，不接入上游自己的更新检查；首版只做本地成绩，不连接其排名服务器或创建匿名设备标识。联网排名属于额外功能，不能因复用游戏代码顺带启用。

## 内存和验证

没有开始游戏时，不启动游戏绘制线程、帧回调、预览缓存或看门狗。游戏中限额加载所需图标，优先用单窗口批量二维绘制，避免照搬每个球一个原生分层窗口。运动/瞄准更新才维持必要帧率，静止、失焦或最小化时降低刷新或暂停；退出后检查进程、句柄、位图和计时器释放。

不承诺“零内存开销”：分别测量未玩过、运行中、退出后和长时间闲置的私有工作集、专用提交及 CPU，并与当前版本同条件对比。游戏进程存在时按所有所属进程汇总，不能只报主进程。

实施先后：物理及合成图标原型 → 接入当前分类 → 加只读桌面来源 → 完整退出和更新联动 → 隔离回归及实机画面检查。测试涵盖碰撞和穿透、白球入袋、重开、DPI/分辨率变化、连续开启、退出、异常终止和后台资源回落。游戏前后核对收纳索引及分类排序哈希不变，再决定是否发布。

原版透明桌面模式是否需要、图标来源及是否启用按需进程，属于接入体验选择。本轮不把方案当作已实现功能，也未改动本机安装。
