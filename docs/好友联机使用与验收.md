# 好友联机使用与验收（0.15.0）

实施依据：[好友邀请联机实施方案](好友邀请联机实施方案.md)。用户选择本轮先完成本机双端测试，真实两台电脑与公网网络另行验收。

## 使用

1. 房主打开「更多 → 桌面玩法 → 图标台球」，选球组与「创建好友房间」。进入游戏后点击「复制邀请」，发给朋友。
2. 朋友选择「加入好友房间」，粘贴邀请后加入。也可从自动搜索出的局域网列表选择房间，无邀请密钥加入需房主允许。
3. 房主为玩家 1、朋友为玩家 2；双方阅读规则并点击准备后开始。双方各显示自己的软件图案，球号和颜色相同。无本地图标时使用默认球面。
4. 仅当前玩家能击球或摆放自由球。球位、犯规、分数、复位和胜负由房主统一判定。
5. 点击请求暂停 / 同意继续，或请求重开，需要另一方同意。联机切换窗口 / 最小化 / 重看规则不暂停对方的整局，返回可操作窗口后恢复本机显示和输入。
6. 朋友暂时断线可在 60 秒内自动恢复原座位和完整状态，不重复执行已接受的击球。超时或房主退出结束本局，未完成局不记正常胜负；没有房主迁移或主机重启恢复。

邀请是包含地址的复制串，有效期 2 小时，不是需要服务器查询的短房间码。可达的同网 IPv4、全球 IPv6 或组网地址均可尝试。TCP 默认 38471，冲突 / 端口受限时改用可用端口并放入邀请；局域网发现 UDP 38472。IPv6-only 网络使用邀请加入。连接失败可查看游戏中的「连接帮助」，确认房间、邀请和双方入站访问条件。

## 实现

网络模块为纯 .NET，与现有 Core 共用规则，随原单 EXE 打包。只有游戏选择联机后才开启监听和连接，普通收纳不运行网络房间。房主固定步长计算，运动中约 20 Hz 快照，客户端插值显示；闲置发布状态，暂停不空转物理或保留绘制循环。

TLS 自签证书通过邀请中的 SHA-256 指纹固定校验；随机邀请凭证与独立恢复凭证绑定座位。发现报文不含邀请密钥，限大小、次数和等待。消息采用有界长度前缀、串行写入与有限快照队列，操作校验席位、请求序号、轮次、基础击球号、数值和状态。

Windows Schannel 不接受直接使用临时 ECDSA 密钥，使用未设置 PersistKeySet 的用户级临时密钥容器；不把证书加入系统信任、不创建应用 PFX 文件，正常释放时清理容器。测试前后枚举确认新增容器遗留数 0，未读取密钥内容。Windows 密钥容器属于系统密码服务位置，不是新增收纳数据目录。

邀请、指纹、密钥和恢复凭证不写游戏成绩或长期日志。网络只传球号、状态和操作，不传软件名称、路径、文件内容或桌面排列。联机完成成绩增加 Connection=online 和本机席位，独立于单人最佳，父进程仍是本机游戏数据写入方。
