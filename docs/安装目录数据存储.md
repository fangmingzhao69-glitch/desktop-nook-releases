# 安装目录数据存储（0.12.13）

## 位置

正式安装使用已登记的安装目录，未登记时使用 EXE 所在目录；主要用户数据统一放在其 `Data` 子目录。本机为 `E:\yingyon\DesktopNook\Data`。

| 位置 | 内容 |
| --- | --- |
| Data/state.json、.bak | 项目、分类及恢复原路径 |
| Data/item-order.json、.bak | 分类内独立排序 |
| Data/preferences.json、.bak | 关闭、窗口尺寸、添加视图及动画偏好 |
| Data/category-policy.json、.bak | 已删除“未分类”等保留策略 |
| Data/vault/项目ID | 恢复清单、快捷方式及实际文件/文件夹 |
| Data/storage.json | 安装目录存储标记及迁移核验信息 |
| Data/updates、Data/shell-menu | 更新包、更新记录及菜单临时副本 |
| Branding | Windows 任务栏可读取的版本化公开图标 |
| Backups | 显式恢复/验收工具在安装目录下创建的备份（按需出现） |

Windows 开机自启、回收站桌面显示及卸载信息仍使用系统注册表；开始菜单和固定入口也保留在 Windows 要求的位置。这些不作为主收纳内容。旧设置注册表只用于首次兼容读取，正常偏好修改只写配置文件。

## 首次迁移

迁移先在安装目录创建独立暂存目录，限制为当前用户、SYSTEM 和管理员访问，再复制旧配置目录。校验文件主数据、命名附加流和空目录；拒绝链接、联接和云占位项，避免跟随到不相关位置。保留 EFS，不采用解密后写入的迁移降级方案。

旧 `.DesktopNookVault` 中被清单引用的真实内容复制到 `Data/vault/ID/content/名称`，清空新的 PayloadPath 绝对定位并同步主索引、备份索引和恢复清单。原桌面路径保留，用于移回；分类归属、名称、ID 和独立排序保持。暂存目录经新存储实例检查后才原子发布为 `Data`；目标已存在且冲突时停止，不覆盖。

原 `%LOCALAPPDATA%\DesktopNook` 和原桌面同盘的隐藏 `.DesktopNookVault` 保留为备份。在旧配置目录中只追加小型 `storage-location.json` 兼容定位信息；新数据已启用后，不使用旧备份覆盖更新过的主内容。正常启动、更多菜单的“打开数据目录”、更新器和维护恢复均使用新位置。

如果旧目录有未完成的收纳日志，先用原版本完成其事务恢复再迁移。复制期间源变化或文件被占用时停止并保留副本。安装目录不可写时明确失败，不静默建立另一套空配置。

## 后续收纳和移回

新普通文件和文件夹以 Data 内为主存储。相同卷优先原子移动；跨卷时先复制到目标卷的独立暂存位置，校验主数据和命名流，再发布目标并逐项移除已核验的源。Windows 文件删除通过有校验的同一文件句柄执行，目录只作非递归空目录删除，遇到新增文件或占用时保留，不盲目递归清除。中断时沿用操作日志恢复，只将完整发布的内容列为主项目。

程序自身、数据目录及包含数据目录的上级目录不能被再次收纳，复制目标不能位于源目录内部。旧位置迁移备份不会因后续编辑自动同步，它们是旧版本快照。

## 兼容和验证

正常安装实例继续使用旧实例身份，避免旧、新保存位置各启动一个写入方。沙箱继续按沙箱根目录隔离，并支持独立 data-root 覆盖，以便验证搬迁后的配置和原桌面身份。

旧更新助手的首次就绪确认仍针对它提供的原目录；确认并退出后，新版在没有拖拽、弹窗、菜单或更新操作时迁移。迁移期间禁用数据操作，完成后切换 Store、偏好和 PID 记录，再刷新原分类。后续更新直接传新目录，不回读旧备份。卸载前使用当前目录移回内容，保留数据及备份目录，不进行真实数据卸载测试。

验证记录：53 项核心检查覆盖跨卷文件/文件夹往返、编辑、空目录及附加流、迁移中断、源变更和不覆盖目标；70 项原生界面、12 项真实拖动、9 项存储专项通过。安装器在专用 TESTROOT 下完成安装、覆盖和卸载恢复，真实用户数据未用于卸载验收。

复现：构建单文件后，运行 `DesktopNook.exe --storage-self-test 独立输出目录`。该检查使用合成数据和隔离注册表，验证迁移副本、文件设置优先、维护退出以及更新后仍读取新目录。常规开发仍必须使用 sandbox。
