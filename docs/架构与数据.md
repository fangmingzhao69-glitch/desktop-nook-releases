## 数据保存

默认数据根目录为安装目录 `Data`，本机使用 `E:\yingyon\DesktopNook\Data`。本机早期迁移留下的 C 盘目录已移入回收站。迁移及跨卷存储见[安装目录数据存储](安装目录数据存储.md)。主目录包含：

- `state.json` / `state.json.bak`：分类与收纳索引及备份。
- `item-order.json` / `item-order.json.bak`：分类内顺序及备份。
- `preferences.json` / `preferences.json.bak`：用户设置及备份。配色和明暗模式分别保存。
- `Notes/`：便签、待办和归档，见[保存与恢复](项目便签实现与验收.md)。
- `migration.json`：进行中的操作日志，用于中断恢复。
- `vault/<id>/`：逐项恢复清单、快捷方式副本或同卷托管内容。
- `updates/`：下载、更新计划、元数据快照及更新结果。
- `instance.pid`：当前实例定位信息。

默认保留“未分类”时仍可使用索引格式 1；显式删除该分类时升级到格式 2，允许没有 `uncategorized` 分类但仍要求至少一个分类。回退收纳目标优先使用“未分类”，否则使用第一个现有分类；正常重开不创建已删除的分类。旧版程序不支持格式 2，不应手动降级读取新索引。

当前安装模式将新收纳的普通文件和目录存放在 `Data/vault`。同卷优先原子移动，跨卷通过暂存、校验和发布处理。旧模式的记录仍可能引用原桌面同卷的隐藏 `.DesktopNookVault`，完整备份也要包含仍被清单引用的外部内容。

收纳普通文件后的编辑会随移回保留。同名目标不覆盖；目录联接、符号链接及未落地的云占位内容不按普通实目录处理。

快捷方式通过内容校验和逐项清单保留恢复依据。操作中断时，根据日志、托管内容及源/目标实际状态恢复。恢复副本及更新备份均保存在本机，不构成云备份。

分类内顺序由独立排序记录保存，并兼容旧版状态文件中的相对次序。保存排序前校验完整且无重复的同分类 ID 集合，原子保存状态和顺序。排序只更新记录。“全部”以分类列表顺序拼接各分类项目，不存储另一套全局顺序。索引和备份都损坏、从逐项清单重建时，最后的自定义顺序不保证完整恢复。

删除分类先原子提交接收分类及图标归属，再同步变更项目的恢复清单。清单被占用等错误会保留有效索引和托管内容并报告警告，不让索引处于半删除状态。

## 偏好与系统入口

窗口尺寸和关闭偏好保存在 `preferences.json`（及备份）。旧 `HKCU\Software\DesktopNook\Settings` 只用于兼容迁移。取消勾选的 false 值明确保留；自启仍使用当前用户的 Windows Run 项。窗口比例只调整窗口，内容维持默认尺度并自动计算列数。

升级绑定原数据目录；启动前核对分类索引和关闭偏好，新进程通过原子写入的就绪记录报告实际读取值，更新助手再确认成功。分类或关闭偏好不一致时停止，避免默认为更新成功。完整备份应包含 `preferences.json` 和 `.bak`。

`category-policy.json` 保留已删除“未分类”的选择；恢复旧索引或从清单重建时应用此标记，避免默认分类复现，相关项目归入现有分类。完整备份也应包含该文件。

回收站收纳保存并调整当前用户 Explorer 的桌面图标可见性设置，移回时还原，不移动回收站内容。

## 在线更新

自动模式优先查询 GitHub `fangmingzhao69-glitch/desktop-nook-releases` 的最新正式版，访问失败时查询 Gitee `zfmdx/desktop-nook-releases`。手动模式只用指定平台检查和下载。自动模式的同版本下载回退沿用已确认的文件大小和 SHA-256。Gitee 从同一标签读取校验清单和程序大小，只接受本仓库的附件路径及官方 CDN。查询和下载均为匿名访问。

下载核对来源、大小、SHA-256、产品名和版本。确认后交给独立助手，等待当前程序正常退出，备份旧程序并替换，再启动新版并等待就绪确认。

更新不迁移收纳内容，会保存元数据快照。替换失败时尝试还原；新版未确认就绪时保留备份和更新记录。

新版优先通过硬链接发布已关闭的完整就绪文件，避免旧助手读取瞬时重命名共享锁；新助手对短暂读取异常重试。公开 ICO 与用户配置分开，优先存安装目录 Branding，不可写时使用 CommonDocuments 按 SID 隔离的公开缓存；加密位置不作为最终缓存，不解除文件或目录加密。

外观名称为折页，DesktopNook 的程序集、AUMID、数据目录、注册表和发行资产名继续用于兼容。GitHub 公共 API 无个人令牌。GitHub API 返回 403、429、5xx、连接异常或超时时，可以改查同一仓库的官方 latest 发行页。程序核验最终地址的仓库及版本标签，再读取该标签的 SHA256SUMS.txt 和 HEAD 文件大小。无效的发行信息或校验失败的文件会被拒绝。所选渠道均失败时，界面报告更新检查失败。

## 验证范围

覆盖故障恢复、同名保护、附加流、文件/目录往返、快捷方式启动、原生 OLE、窗口大小、图标像素和更新。原生检查需要可交互 Windows 桌面。

混合 DPI 多屏的完整组合仍待实机覆盖。Shell 扩展、公共桌面权限和图标原资源质量受具体系统及应用影响。

## 轻量发布与图标缓存

使用依赖共享 .NET 10 桌面运行时的单文件发布，兼容 EXE/程序集/更新资产名均不变。安装器在停止旧程序前检查 x64 桌面运行时，缺少时可在交互安装中提示补装。Windows 运行时安装登记可能位于 32 位或 64 位注册表视图，均只读检查。早期退出信号会在等待应用互斥量期间重试，处理应用已持有锁但尚未注册退出事件的启动窗口。

Shell 图标仅在可视区域加载；控件离开可视区域或卸载时释放图片引用。缓存限 8 MiB 原始像素及 256 项，工作线程将完成的冻结图片只送给匹配控件。分类切换的 Unloaded 事件可能晚于控件移出界面树，因此坐标转换前核验祖先关系。预算不包含控件持有的图像或 WPF/GPU 副本。
## 添加视图偏好与运行时补装

preferences.json 增加可选 CollectView（icons/details），未选择时不写该字段，首次默认 icons；已有关闭偏好与窗口尺寸保持。设为默认时才保存，切换视图不修改默认。Snapshot 汇总现有设置，窗口大小、关闭行为和更新就绪保存都携带该字段，避免相互覆盖。选择控件对象跨视图复用，图标按原 ShellIcon 懒加载。0.12.7 起使用专属 ToggleButton 模板，只绘制选中背景与边框，不渲染勾选框；各项独立切换，支持连续多选和键盘空格。

安装器只在交互安装并取得确认后补装；静默缺运行时返回 23，用户取消返回 1602，补装失败返回 24，安装后复核仍缺少返回 25。SHA-512 和微软签名验证通过后仅提升微软组件安装器，退出码 0/3010 视为成功并重新检测运行时；3010 提醒稍后重启，不设置轻匣安装器自动重启。只有确认运行时可用才停止旧程序并安装折页。
## 独立顺序记录、商店图标与添加窗口边界

item-order.json 与 .bak 按分类保存项目 ID 序列，是独立排序记录，不是恢复项目的清单。每次保存先验证完整状态，再原子写排序记录及状态索引；所有增删和分类移动同步更新，回到原分类的项目仍按移动规则追加。加载时只对当前索引已有且仍属该分类的项目应用顺序，未记录的新项目保留相对顺序追加，不改变成员归属或恢复已删除内容。主索引损坏时可配合逐项清单保留现有分类的顺序；未记录的历史顺序无法推断。更新助手的元数据快照包含两份排序文件。

普通图标仍通过后台 Shell 图像工厂获取。商店快捷方式先取得 AppsFolder 身份，再从该注册项读取 PackageInstallPath 和 SmallLogoPath，限定在对应安装根目录内选择 PNG 资源，根据实际像素尺寸和浅色界面变体择优。读取失败才回退到 Shell 提取；不修改商店应用、快捷方式、WindowsApps 权限或加密属性。

添加窗口在 SourceInitialized 时按实际 Owner 宽高计算上限（88%），并受所属屏幕工作区约束，缩小最小尺寸约束以适应小主面板。限制 MaxWidth/MaxHeight，保留正常 DPI 文字与滚动区，不对文字做整体缩放。
## 动画管理

UiMotion 用目标对象/属性索引管理短时动画时钟，新的过渡从当前视觉值替换旧时钟，完成或卸载时移除。反馈状态以 ConditionalWeakTable 关联控件，未运行时没有持续动画计时器。颜色刷为各控件私有，避免修改共享冻结资源；主按钮只改变独立白色覆盖层，保留渐变。

窗口状态仍由原有主窗口路径同步处理，动画完成回调不设置 WindowState。最小化立即取消全部动画；实际任务栏定位变化之前结束面板过渡，同位置定位不打断入场。所有位移使用 RenderTransform，拖拽开始前清除，不修改布局尺寸、分类顺序或恢复数据。

preferences.json 新增可选 MotionMode（system/on/off）；未配置时忽略空字段并默认跟随系统。Snapshot 同时保留关闭行为、窗口大小、CollectView 和 MotionMode，跨设置和升级验证都覆盖该偏好。UI 运行时缓存动画模式，悬停时不读取配置文件。Windows 客户区动画设置变化时在 UI 线程重新应用模式。

## 闲置释放

ShutterMotion 改为与正交旋转对应的二维分段缩放，池中仅保留五段视图及一份限额截图，活动时钟完成即拆除。截图像素预算 8 MiB，内容、图标、滚动及尺寸变化后重采；原始像素预算不等于 WPF/显卡总占用。主面板最小化即暂停 ShellIcon、清除控件图片，5 秒无操作后释放池及截图、裁剪图标缓存至 2 MiB/64 项，并按代次废弃旧图标工作。

闲置时断开本窗口 HwndSource.RootVisual 并暂设 HwndTarget.RenderMode=SoftwareOnly；保留 HWND、逻辑视图和业务状态，显示时恢复原渲染偏好及绘制根，不创建额外常驻进程。原生恢复和应用唤醒均覆盖此路径；重连期间窗口遮罩避免原生消息重入导致整板闪现。Loaded 再入不重复初始化后台定时器，数据操作及更新忙碌时不执行闲置拆除。没有强制 GC 或工作集裁剪。

## 安装目录存储
DataPaths 统一目录选择，StorageRelocation 在暂存副本中迁移实际内容及所有清单，通过后原子发布。迁移时保留原位置作为备份。VerifiedContent 校验主数据和文件/目录命名流，StoreAllPayloads 模式不再将新主内容回落到旧隐藏文件库。更新保留显式数据根，维护/恢复工具读取当前位置；偏好为文件优先且停止注册表设置镜像，Windows 自启等系统入口保留。

## 图标台球

DesktopNook.Games.Core 保存纯物理与回合状态。主进程的 BilliardsController 只在开始游戏时创建，使用当前用户专属随机管道启动同一个 EXE 的 --icon-billiards 分支。双方核对管道对端 PID、启动时间、EXE 与 nonce；该分支在普通单实例、NookStore 和偏好初始化前处理，不成为第二个收纳数据写入方。

BilliardsWindow 单个自绘场景在游戏进程提取最多 45 张 128 像素图像，球体复制共享图像；运动阶段按合成帧时间限制到 60 FPS，静止/暂停不保留帧订阅。父进程只接收设置及经会话、轮次、范围验证的完成成绩，去重后原子写 Data/Games/IconBilliards/settings.json 与 scores.json。成绩结构单独保存历史最佳及最多 100 局 Recent，不因滚动清单丢失最佳。

关闭、更新和存储维护先停止游戏并排空接收中的成绩；IPC 接收在后台执行，避免 UI 同步退出等待死锁。协议异常断管，游戏检测父进程/连接丢失后退出。关闭超时仅核验并结束本会话子进程。游戏不读写主索引、顺序或托管文件，不操作 Explorer 图层。

### 固定球组与圆球

BilliardsRules 统一四个球组的 ID、名称、数量和配色。GameSettings.Rule 持久化球组，Count 为派生只读值；启动及成绩消息校验 Rule / Count，旧自由数量默认中八。GameStorage 增加 BestByRule，保留旧 Best 和 Recent；不同规则成绩不混排。BilliardsBallDrawing 以冻结 DrawingGroup 缓存圆形球面、裁切图标小标及编号，切换来源图片或 DPI 时失效，退出随游戏进程释放。

游戏窗口从程序所在屏幕计算初始尺寸和位置，窄窗口工具栏分行。开源许可可从主菜单打开。

### 球盘、音效与双人

BilliardsRound 记录每杆首次接触、进袋顺序和接触后碰库，在静止结算时交给纯核心 BilliardsMatch 决定计分、换人、复位、自由球和胜负。单人仍沿用清台，双人成绩按 Players 独立验证且不进入单人最佳。BilliardsTray 复用圆球绘制，白球排除、复位移除，双人按击球方分排。

规则卡在 Ready 阶段等待确认，确认后才可击球和计时。游戏窗口默认占所在屏幕约 40% 面积并居中。

BilliardsTray 按 side 在球台两侧显示双轨槽体，冻结框体绘图并按尺寸复用；游戏图案占比从 0.48 放大到 0.70。Core 的 BilliardsAudio 从程序集加载经过许可核验的 PCM，选取轻重击片段并缩放振幅。游戏 BilliardsSound 使用按需音频工作线程混合最多六声部，waveOut 两个 20 ms 缓冲；停止通过代次丢弃旧声音，线程闲置阻塞等待，退出释放。来源与构建方式见[开发与构建](开发与构建.md)。

### 好友邀请联机

Games.Network 使用 TCP/TLS、临时邀请与恢复凭证、UDP 局域网发现。房主独立 Core 对局固定步长，窗口应用只读 RoundView 并插值，不在两端各算结果；当前方和基础击球号由房主核验。Source/图标名称/路径不进入网络帧，软件图案各端自用。联机 Connection / LocalSeat 成绩仍由本机父进程保存，不进入单人最佳。失焦只影响本机输入/绘制；房间暂停、重开需要双方同意，短断线保留状态，房主退出结束。[好友联机使用与验收](好友联机使用与验收.md)

## 任务栏外观

NativeTaskbarBackend 在折页主进程中启停任务栏外观组件。首次启用时下载并校验组件，现有场景及偏好保存在应用数据目录。停止外观时恢复系统效果。任务栏定位及外观控制分别由 TaskbarPlacement 和外观组件处理。
