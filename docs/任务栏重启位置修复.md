# 任务栏重启位置问题（0.15.1）

2026-11-16 用户反馈重启后轻匣任务栏位置不保留。现场发现固定目录有轻匣.lnk、桌面小筑.lnk 两个同目标 / 同 AUMID 文件；当前任务栏呈现一个运行按钮。不能仅凭两个文件认定 Windows 注册了两个固定按钮，亦不能从现状恢复用户希望的位置。

代码存在启动时扫描并改写固定入口的逻辑，且图标地址随软件版本改变；这些是可能干扰入口识别的因素，尚未通过真实重启确认确切根因。

修复：普通启动仅刷新公共图标和安装信息，不改任务栏或开始菜单快捷方式；正常路径不再隐式枚举固定目录。图标按内容哈希命名，保留已有版本图标。显式迁移仍可用于独立测试目录，保留目标、参数、工作目录和名称。不操作系统 Taskband 顺序、不重启 Explorer、不擅自删除旧名固定入口。

隔离检查 8 项通过，含连续 5 次启动刷新保持固定文件字节 / 时间戳及开始菜单入口。

已从推送提交 de673a2f9b72f6ec1414729fdfcfffa0c0dfe0bc 构建并公开 0.15.1，服务器三个资产摘要与本地一致。本机安装位置覆盖升级后，连续 3 次以真实 --autostart 启动，所有固定快捷方式的文件名、字节和修改时间均未变化；两个属于轻匣的入口继续指向当前 EXE，AUMID 保持 DesktopNook.DesktopNook，历史图标仍存在。58 项 / 7 分类、当前主元数据、13,281 文件 / 311 目录的路径与正文摘要、两份游戏数据文件均保持。item-order.json.bak 被原有启动逻辑正常轮换为升级前的当前排序，主排序文件未变；最初将所有 .bak 也要求不变的严格检查失败，经逐文件核验确认只有这项预期变化，未回写旧数据。

同盘旧程序、公开图标、元数据 / 逐项清单和游戏数据备份：E:\yingyon\DesktopNook.UpgradeBackup-0.15.0-20261116-211441。归档旧交付包的组合命令被自动审批拒绝（仅返回 blocked by policy，未提供具体原因），因此发布/轻匣-v0.15.0 原包保留，新包在发布/轻匣-v0.15.1。见[实机核验](验证结果/任务栏实机升级核验.json)。

用户可把图标拖回希望的位置一次。重启验收需下次真实重启；本轮没有重启电脑或 Explorer，不能将连续程序启动等同于系统重启，也尚不能确认重启移位的唯一根因。
