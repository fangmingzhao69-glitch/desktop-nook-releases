# 轻匣任务栏外观整合方案

2026-11-18 · 规划稿

建议把该功能做成轻匣的「更多 → 任务栏外观…」。轻匣统一提供设置、预览、开关和开机启动入口，TranslucentTB 作为可选的独立组件处理 Windows 任务栏外观。用户只需在轻匣操作。组件关闭或无法运行时，轻匣的收纳、便签和任务栏入口仍可正常使用。

## 现状和首要验证

| 项目 | 现场依据 | 对整合的影响 |
| --- | --- | --- |
| 轻匣 | 当前正式版 0.16.5，WPF、.NET 10、x64 单文件。已用同一应用入口管理自启、更新及退出 | 外观设置复用现有菜单和弹窗，自启沿用轻匣入口 |
| 上游基线 | 工作区 `TranslucentTB` 为官方 2026.2 的 `d4636e4`，工作树干净 | 固定源码基线和依赖版本，便于复验及归档许可证 |
| 本机修复包 | `TranslucentTB-build/out` 保留修复版安装包及补丁。已只读检查补丁可应用到当前基线。历史记录使用 26H2 `26340.9750`，独立版曾通过安装与透明显示验收 | 能作为复现线索。现有安装包和历史结果无法替代本次重新构建、校验及实测 |
| 当前环境 | Windows 26H2 `26340.9882`，`E:\yingyon\TranslucentTB` 有独立进程在运行，旁边存在配置文件 | 验收从当前构建号开始。整合启用前应提示用户如何交接当前外观，保留独立版及其设置 |

26H2 的任务栏结构变化曾使上游 2026.2 找不到需要改变外观的任务栏。历史修复包采用 PR #1371 中的结构匹配修正。该 PR 已关闭，所用补丁应作为本机分支的修复来维护。历史记录还提到 Explorer 重建后可能要等待任务栏就绪，首版要验证功能能自行恢复。[官方 2026.2 发行](https://github.com/TranslucentTB/TranslucentTB/releases/tag/2026.2) · [上游兼容性讨论](https://github.com/TranslucentTB/TranslucentTB/pull/1371)

## 首版交互

- 首批支持经验证的 Windows 11 x64 构建。Windows 10 和 ARM64 单独评估和验收。
- 「启用任务栏外观」默认关闭。支持系统默认、透明、纯色和颜色调整。模糊、亚克力仅在当前系统上分别验证后提供。
- 支持预览、应用、取消和「恢复系统外观」。预览不提交设置，关闭设置窗口、取消或预览超时都会回到上次已应用的外观。
- 轻匣收起和最小化时继续显示已启用的外观。关闭该功能、真正退出轻匣时请求组件清理并恢复系统任务栏。以后每次登录是否应用，由轻匣已有的「开机自启」和任务栏外观开关共同决定。
- 发现独立版已经运行时，显示「已有 TranslucentTB 正在管理任务栏」。用户可以继续使用独立版，或复制现有设置后在轻匣接管。首次接管先由用户退出独立版。启动项的变更需由用户明确选择。
- 第二阶段再做随桌面、普通窗口和最大化窗口切换的配置。开始菜单、搜索、任务视图、逐屏配置和例外规则放到后续。动态场景沿用经过验证的上游检测和配置语义。[上游配置结构](https://github.com/TranslucentTB/TranslucentTB/blob/2026.2/settings.schema.json)

## 结构和数据

| 层 | 职责 |
| --- | --- |
| 轻匣 WPF | 复用「更多」菜单及蓝青弹窗。显示组件状态，负责预览、应用、恢复、接管和错误提示 |
| 外观管理 | 当前用户会话内按需启动和停止受管组件，记录已应用状态，检查是否已有独立版管理同一任务栏。用窄接口交换设置、状态和停止结果，不共享收纳数据库或业务对象 |
| TranslucentTB | 独立目录和进程，固定经过测试的 x64 版本。按其配置格式加载外观，在组件退出时触发原有的外观清理流程 |
| 数据 | 轻匣外观设置存于 `Data/TaskbarAppearance/settings.json`，含格式版本、启用状态和已保存的外观。组件运行配置由它单独生成。更新备份包含外观设置，原独立版配置可只读导入并原样保留 |

先验证上游便携模式的配置热重载、单写入方和正常退出语义。进程存活与配置已写入分别确认，另以组件状态或实测证据判断外观是否真正应用。若需要补充轻匣可调用的状态和停止接口，作为 TranslucentTB 独立分支的少量改动维护，并随其对应源代码交付。遇到 Explorer 尚未就绪时显示等待状态，有限次重试，失败后回到可恢复状态，避免反复启动组件。

## 打包和升级

首选保留轻匣单 EXE 和安装包的交付方式。外观组件首次启用时，在用户确认后下载固定版本，并按清单核验 SHA-256、体系结构和路径，再放入轻匣专用的版本目录。安装版与免安装版走同一组件流程，普通轻匣安装和更新保持现有的大小目标。依赖及实际体积在原型阶段测量。现有独立版优先用于迁移和对照验收，历史 Inno 安装程序留作回滚材料。

组件和轻匣可分别升级。先暂存并校验新版组件，再确认旧组件清理成功，最后换用新版。新版无法应用时可恢复上一个已验证版本，或恢复 Windows 默认外观。轻匣退出、程序更新、存储搬迁和卸载前接入相同的正常停止流程。轻匣固定位置、快捷方式、AUMID 和系统自启登记继续由各自现有入口维护，外观层只负责样式。

TranslucentTB 使用 GPLv3。发行修改版二进制时，应保留许可与署名，并提供与实际发出的组件对应的源码、补丁及构建脚本。独立进程是隔离设计的一部分，发行前仍需复核组件和轻匣之间的耦合方式与许可边界。直接并入 WPF 进程会增加兼容和许可处理成本，因此推荐独立发布组件并由轻匣管理。[上游许可证](https://github.com/TranslucentTB/TranslucentTB/blob/2026.2/LICENSE.md) · [GNU 许可证 FAQ](https://www.gnu.org/licenses/gpl-faq.en.html#MereAggregation)

## 实施顺序和放行条件

| 阶段 | 交付 | 放行条件 |
| --- | --- | --- |
| 1. 外观组件验证 | 在独立构建目录复原 2026.2 基线与经审查的任务栏匹配修复。检查依赖、组件校验、重载和退出能力 | 在匹配当前 `26340.9882` 的测试环境里确认透明、纯色、恢复系统外观。另测至少一个常用 Windows 11 正式版本。不同版本实测结果分别记录 |
| 2. 轻匣设置与交接 | 新菜单、开关、预览、设置存储、可选导入及独立版冲突提示 | 取消和超时恢复正确。多次启停无残留。验证正常退出、组件异常退出、Explorer 重建、主题切换、自动隐藏及主副屏与混合 DPI |
| 3. 升级与正式发行 | 校验组件和本地回滚。轻匣源码推送，安装包和单文件 EXE 发布。提供组件对应的源码和许可 | 旧版能检测并下载新版。安装、更新失败、组件替换和卸载按隔离流程复核。核对便签、收纳及固定入口状态。对比启用前后轻匣、组件和 Explorer 的 CPU、内存，记录数据 |

普通 `--sandbox` 只隔离轻匣数据，无法隔离当前登录会话的任务栏。涉及实际外观、Explorer 重建、卸载和登录验证时，使用虚拟机或独立测试会话。若某系统构建无法通过外观验证，仍可使用 Windows 默认外观，并提供到系统任务栏设置的入口。[Windows 任务栏设置](https://support.microsoft.com/en-us/windows/experience/personalization/customize-the-taskbar-in-windows)
