# 软件体积与运行内存评估（2026-11-10，0.12.5）

用户已确认接受依赖共享运行时，主程序尽量小。0.12.5 使用依赖 .NET 10 Windows Desktop Runtime x64 的轻量单文件，保留所有功能和兼容标识。早期实验结果保留用于说明取舍，正式结论见文末。

## 测量口径

当前安装 EXE 140,283,533 字节（133.78 MiB），安装包 43,179,162 字节（41.18 MiB）。最初日常进程一次采样：工作集 248.54 MiB、专用提交 149.01 MiB。两者不是同一个内存指标，工作集包括共享和可回收页面，专用提交也不等于当前驻留物理内存。运行时计数器显示托管堆已提交约 23.8 MiB，不能将全部进程内存归为图标缓存或 GC 堆。

对比使用独立 --sandbox：复制当前 56 项的分类与快捷方式元数据，普通文件/文件夹仅用微型测试内容代替，不读取或移动其正文。采样在 WaitForInputIdle 后第 5、10、15 秒；下表列最后一次采样。生产程序含后台更新、品牌入口迁移、历史操作等，对比表不能直接与日常进程一次采样混算。预热后的原版与图标优化版单独比较；首轮启动有解包、系统缓存和扫描干扰，WaitForInputIdle 也不代表全部图标已就绪，因此不据此宣称启动提速。

## 保留在工作区的开发改动

- Shell 图标完成通知只发给匹配控件，避免 N 个图标加载引发 N×N 次调度。
- 可视区域外不发起图标加载，并释放控件当前图片引用；滚动回来重新取缓存或加载。
- 最近使用缓存限制为 8 MiB 原始像素预算及 256 项。这个预算不包含控件引用、WPF/GPU 副本或其他进程内存，不能解释为软件总内存上限。

同一预热场景的工作集降低约 4.8%，专用提交降低约 1.6%，CPU 累计采样约降低 19%。这些是首轮实验结果，不能据此承诺日常常驻内存降到几十 MiB。GCConserveMemory 与软件渲染实验没有证明稳定的整体优势，因此未写入正式配置；未调用工作集清空，也未加入定时强制 GC。

## 0.12.5 正式方案与最终隔离结果

主程序约 741 KiB，安装包约 368 KiB（最终准确字节数与 SHA-256 以正式包为准），不包含共享运行时。运行时最低为 .NET 10 Windows Desktop Runtime x64，采用该主版本的已安装补丁，不强行要求 SDK。SDK 不允许为依赖运行时的单文件启用 EnableCompressionInSingleFile，未启用该开关。

固定 56 项隔离场景，最后一次预热采样：工作集 203,051,008 字节（193.64 MiB），专用提交 121,868,288 字节（116.22 MiB）。相对于原版预热的 206.50/117.96 MiB，工作集约降低 6.2%，专用提交约降低 1.5%。CPU 累计采样 2343.75 ms，原版 3234.375 ms，首屏负担也有下降；不是长期压力测试或日常进程等价对比。

通过：42 项核心、37 项完整原生、11 条图标专项、13 项在线更新检查、0.12.4 原助手升级到 0.12.5、独立安装/覆盖升级/卸载并恢复 7 项测试内容。运行时缺失分支通过专用安装器宏模拟，退出码 23，安装路径未创建，真实进程保持运行；未卸载用户电脑的运行时做测试。

安装回归还暴露旧停止逻辑只发送一次退出信号，早于主程序注册事件时会漏掉。现改为在等待互斥量期间重试，覆盖升级回归通过。图标缓存预算只限制缓存持有的原始像素，不代表全进程总内存只有 8 MiB。
